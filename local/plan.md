# Comprehensive Hospital Record System (HRS) Architecture Plan

## 🏥 1. System Vision & Domain Model
The HRS is evolving from a basic EMR to a **Template-Driven, Task-Oriented Inpatient Management System** bound to a single hospital facility. The core philosophy is to minimize cognitive load on execution staff (Nurses/Pharmacists) by having high-level staff (Admins/Doctors) define deterministic protocols (Templates).

### 1.1 Core Entities
- **Facility**: The singular hospital context (includes configuration, total beds, base pricing).
- **Users**: Staff (Admin, Doctor, Nurse, Pharmacist) and Patients. All signups default to `inactive` pending Admin approval.
- **Beds/Rooms**: Physical locations auto-allocated to admitted patients.
- **Disease Templates (Protocols)**: Pre-defined care plans created by Admins/Lead Doctors. Contains:
  - Required Metrics (e.g., Blood Sugar, BP) and Frequency.
  - Required Medications, Dosages, and Frequency.
- **Admissions (Episodes of Care)**: A patient's current stay, linking them to a Bed, a Doctor, and a specific Disease Template.
- **Tasks (The Execution Layer)**: Discrete actions auto-generated by the Admission's Template.
  - *Nurse Tasks*: "Go to Room 101, Collect Blood Sugar", "Go to Room 102, Administer 500mg Paracetamol".
  - *Pharmacy Tasks*: "Prepare 500mg Paracetamol for Room 102".
- **Billing/Ledger**: Financial tracking of all executed tasks, room charges, and base admission fees.

## 🔐 2. Role-Based Workflows & Access Control

### 2.1 System Admin (The Orchestrator)
- **User Management**: Approve/reject pending signups, change roles, deactivate/delete accounts.
- **Facility Management**: View, add, or modify Bed/Room allocations.
- **Template Management**: CRUD operations on "Disease Templates" (defining standard care protocols and associated base costs).
- **Global Settings**: Manage hospital-wide settings.

### 2.2 Doctor (The Strategist)
- **Patient Intake**: Register new patients.
- **Admission & Protocol**: Admit patients, auto-allocate an available bed, and assign a specific "Disease Template" based on diagnosis.
- **Overrides**: Ability to add custom medications or metrics on top of the standard template.
- **Settings**: Update professional profile (specialty, credentials).

### 2.3 Nurse (The Executor)
- **Task-Based Dashboard**: The traditional patient-list is replaced/augmented with a **Time-Based Task Queue**.
- **Blind Execution**: Nurses see tasks like: `[10:00 AM] Room 204: Administer Insulin` or `[11:00 AM] Room 105: Record SpO2`. Deep patient medical history is hidden by default to preserve privacy and focus on execution.
- **Settings**: Update basic profile details.

### 2.4 Pharmacist (The Supplier)
- **Fulfillment Dashboard**: Sees a daily/shift aggregation of all medications required by the active templates.
- **Delivery Routing**: Sees which room requires which medication.
- **Printing**: Can print physical fulfillment manifests/receipts for medication carts.
- **Settings**: Update basic profile details.

### 2.5 Patient (The Consumer)
- **Status Dashboard**: Fix the missing dashboard. Show current admission status, assigned bed, and estimated course duration.
- **Care Analytics**: Visual progress of their care (What tasks were completed today, what was missed).
- **Financials**: Live view of accruing costs (Room charges + Executed Medication charges).
- **Discharge & Billing**: Download and print the final, itemized hospital bill.
- **Settings**: Update personal details (emergency contacts, allergies).

## 🛠 3. Technical Architecture Updates

### 3.1 Database Schema Additions (MongoDB)
- `users`: Add `department`, `specialty`, `approvedBy`.
- `beds`: `{ id, roomNumber, isOccupied, currentPatientId, dailyRate }`
- `templates`: `{ id, name, description, metrics: [{ name, frequencyHours }], medications: [{ name, dose, frequencyHours, cost }] }`
- `admissions`: `{ id, patientId, doctorId, bedId, templateId, status (active/discharged), startDate, endDate }`
- `tasks`: `{ id, admissionId, type (metric/medication), targetTime, status (pending/completed/missed), executedBy }`
- `billing`: `{ admissionId, lineItems: [{ description, amount, date }], total }`

### 3.2 UI/UX Restructuring
- **Settings System**: Implement a global `/settings` route utilizing `DashboardLayout`. Render different form fields based on the user's role (e.g., Doctors see "License Number", Patients see "Emergency Contact").
- **Task-Driven UI**: Shift Nurse and Pharmacist dashboards heavily towards data-tables grouped by time and location (Room Number) rather than patient names.
